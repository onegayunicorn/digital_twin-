# Cloudflare Asset Directory Fix

The deployment error means Wrangler evaluated `assets.directory` before the frontend build created that directory. In this repository, the active manifest is at the repository root and points to `./web-app/dist/public`.

## Required Cloudflare dashboard settings

| Setting | Value |
| --- | --- |
| Root directory | `/` |
| Build command | `pnpm build:verified` |
| Deploy command | `pnpm deploy:raw` |
| Build variables | None required |
| Node version | `24.18.0` |
| pnpm version | `10.11.1` |

The simpler equivalent is **Build command** `pnpm build` and **Deploy command** `npx --yes wrangler deploy`, but the verified commands are preferred because they run the artifact preflight before Wrangler evaluates the asset directory.

## Why the error occurred

`wrangler.jsonc` contains:

```jsonc
{
  "assets": {
    "directory": "./web-app/dist/public",
    "not_found_handling": "single-page-application"
  }
}
```

The directory is generated by `web-app`’s Vite build. If Cloudflare has **Build command: None**, it goes directly to deployment and the directory does not exist. Do not change the manifest to `./dist` unless the Cloudflare root is changed to `/web-app` and the Worker is intentionally deployed as a standalone package.

## Local verification

From the repository root:

```bash
pnpm install --frozen-lockfile
pnpm build:verified
pnpm preflight
pnpm exec wrangler deploy --dry-run
```

The dry run should report that it read the generated files from `web-app/dist/public`. This is a non-publishing check.

## Recovery rule

If the dashboard still shows `Build command: None`, update the dashboard setting and retry the build. If the dashboard root is anything other than `/`, restore it to `/` or update both the manifest path and scripts as one tested change. Do not publish with a path that has not passed the local preflight.
